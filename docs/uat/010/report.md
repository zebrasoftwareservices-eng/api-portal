## Findings

**Major: Revoke-on-restrict leaves admin-assigned subscription keys working.**

1. Create an Open product with Basic and approval-required Partner plans; obtain active self-service/approved subscriptions for two teams.
2. Switch to Manual using Keep, assign Basic to a third team, then have that team's Admin reveal its key. Confirm `/sample/get` returns 200.
3. Switch back to Open, select Hidden, and save with Revoke them. The confirmation incorrectly counts only two teams/three subscriptions, omitting the assigned subscriptions.
4. In this walk Kong was stopped at confirmation: only the self-service/approved subscriptions appeared as Revoke pending. Restore Kong; wait for automatic retry and refresh the admin page.
5. Original approved key now returns 401, while `uat-team-b-assigned` still shows Active/Not revoked and its original key returns 200. Approval-toggle confirmation likewise omits these assigned subscriptions.

Expected AC12: every existing subscription/key is counted and revoked when the admin chooses Revoke. Actual: assigned subscriptions remain usable. Failure image: `restrict-assigned-key-fail.png` (key suffix only, no secret). The required major Bug creation was attempted and Linear returned “Usage limit exceeded.” Elango subsequently instructed that this bug must have no Linear issue now or later: the Deferred Linear section was removed, while the open bug and backend Fix task remain in the spec. The image stays local and uncommitted.

**Minor: Mobile plan layout overflows.** Open `/products/uat-partner-access`, apply 390×844 mobile viewport, and scroll to Plans. The caption and both plan cards form three narrow columns; measured width is 410px in a 390px client viewport. Requesting still works. Evidence: `mobile-plan-layout-fail.png`.

**Minor: Escape loses the approval trigger focus.** On `/admin/requests`, Tab to Approve, Enter, Escape, then Tab. Focus returns to BODY and starts at Skip to content rather than the original trigger. Approval remains possible by tabbing back. No screenshot, because focus destination was verified through the active DOM element rather than a visual defect needing an image.
