## product-manager · 2026-11-18
Wrote spec 024 (Admin sidebar shell) as a draft with 10 Given/When/Then criteria. They cover the admin sidebar and the Admin group, a read-only Apps list showing key hints, hidden developer actions, and a server 403 when an admin creates an app or requests access. They also cover the Accounts rate-limit fields and one shared chevron, with failure paths for the server refusal and invalid rate-limit input. There was no research brief and no roadmap row. Open questions: which design is "the approved shell", the developer layout, admin visits to developer URLs, apps that admins already hold, the admin Apps endpoint, the existing rate limits, and a possible split into two pull requests.

Tech lead (design): Added ADR 0017 (a portal admin is not a developer) with one server guard, 403 `/problems/admin-not-developer`, on the five developer write endpoints that create keys or requests, and two read-only endpoints, `GET /v1/admin/apps` and `GET /v1/admin/apps/{appId}`, that return key hints only. No migration and no adapter calls. The three Accounts rate limits already have max and window-in-minutes fields, so AC 9 is a form change. The design fits one PR, and the provisional defaults for Elango's open questions (redirect `/dashboard` to `/admin/apps`, leave apps admins already hold) are written in the Technical design.
