
**Design (tech-lead, 2026-11-15).** Search is computed at query time from `publishedApis(db, viewer)`, the same function behind the catalog, so visibility, publish state and latest version can't drift and there's no index, migration or new container (ADR 0012). Added `GET /v1/search` (`q` 1–100 chars, `limit` ≤ 50, 60/min anonymous per IP and 120/min per user) to `openapi.yaml`, with a pure `searchCatalog` matcher in `@portal/sdk` shared by the server and demo mode. Ten tasks are split across backend, frontend and QA; the main risks are operation deep-link anchors in Scalar and per-search cost on large catalogs, each with a named test.

**Factory (from the JSO-239 grade, 2026-11-15).** QA's task now says to run the full suite and the browser suite once, after the new tests pass, and to commit those tests when the guard names another role's files. The backend role now says to read `onDelete` before a delete or reset, and to reuse the gateway propagation wait a sibling path already uses.

**ui-designer (2026-11-15).** Wrote docs/design/020-api-search.md. Search is a GET form in the site header (an icon button below 1024px) that opens a shareable `/search?q=` results page with one ranked list. There is no ⌘K palette and no search-as-you-type, which keeps requests within the 60/min anonymous limit; both are recorded as follow-ups. The design covers start, loading, success, truncated, empty ("Nothing matched" plus Browse all APIs), inline 400, 429 and network-error states, and adds a token-only `MethodBadge` with no new tokens. Status is now building.
