# 011 — Usage meter per app and admin insights

## Product manager (2026-11-14)
Wrote the draft spec from JSO-239 with 10 Given/When/Then criteria: the app usage bar against each plan's monthly quota, status-class counts, team-only access, a stale-data notice, admin insights (sign-ups, active apps, top APIs, time to first call) and the adapter conformance usage test. Error spikes per team, charts, alerts and AWS usage are cut to keep it one pull request. Open questions for the tech lead cover the collection mechanism, retention and matching Kong's quota counter; Elango decides when time to first call starts and whether error spikes get a follow-up.

**Product manager — Elango's answers (2026-11-14).** Recorded Elango's three decisions in spec 011: time to first API call runs from sign-up (account creation) to the first 2xx call through Kong with any portal key on the account, try-it included (criterion 8). Error spikes per team is a follow-up in the spec, to evaluate at a team 5xx rate over 5% across 15 minutes with at least 50 requests. The hosted live demo behaves like any install, with visitor usage meters, admin-only insights and usage cleared by the daily reset, now covered by new criterion 11. Status stays draft; the four tech-lead questions remain open.

**Product manager, tightening pass (2026-11-14).** Made criteria 1, 4, 7, 8 and 10 directly testable: when the page is read, the exact reset-date wording, rolling-30-day and fewer-than-five/no-calls cases, list order and how the median is computed and shown when nobody has called, and a test adapter for the unsupported-usage case. Scope and Elango's decisions are unchanged and status stays `ready` as Elango set it. Added open questions on plans with no quota, plan change or key regeneration mid-month, time to first call for developers joining a team that already has traffic (Elango), and whether the spec fits one pull request.

**Product manager, Elango's answer (2026-11-14).** Elango asked for industry practice on time to first call with team-owned apps. TTFC is a per-developer metric (Postman, Nordic APIs), so criterion 8 now counts only 2xx calls made with a key the developer created or regenerated, and a teammate's traffic leaves a new member at "No call yet".

**Design (tech-lead, 2026-11-14).** Usage is pushed by a consumer-scoped Kong `http-log` plugin on every app, with headers and bodies stripped in Kong. The server stores only daily counts per app, UTC day and service, plus each developer's first 2xx call through a key they created (new `credentials.created_by`). A one-minute heartbeat route lets the app page say usage is behind instead of showing zero (ADR 0011). The contract adds `GET /apps/{appId}/usage`, `GET /admin/insights` and the token-protected `POST /internal/usage/kong`; the spec stays one pull request and is now designed.
