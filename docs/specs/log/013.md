## Product manager — 2026-11-16
Wrote the draft spec from JSO-241: one theme per install covering logo, favicon, brand colours, font, corner radius, light and dark mode, custom CSS with live preview, reset to default, and JSON export and import. Safe mode is the admin area never loading custom CSS, so a bad rule can't lock admins out. Ten Given/When/Then criteria include failure paths for bad uploads or imports (400) and non-admins (401/403). Open questions cover brand colours in the admin area, applying a theme at boot for GitOps, logo and SVG limits, the font list, custom CSS limits, and whether the contrast warning blocks saving.

**Technical design (tech-lead, 2026-11-16).** Postgres stores the theme: a singleton `theme_settings` row and `theme_assets` (logo and favicon as bytea). The server serves it at runtime as `/v1/theme`, `/v1/theme.css` and `/v1/theme/custom.css`, with etag cache-busting, so a save is live on the next page load with no rebuild (ADR 0016). Custom CSS is a separate stylesheet that a client component never links under `/admin`. The editor previews drafts in a same-origin iframe, so broken CSS can't reach the admin area. The contract adds 4 public and 5 admin theme routes, and tasks are split into 5 backend, 5 frontend and 2 QA. Tech-lead defaults for the open questions: PNG/SVG/WebP logos up to 512 KB with an SVG deny-list and a sandbox CSP, six self-hosted OFL fonts, a 64 KB custom CSS cap with `@import` rejected, a fully default admin area, and contrast warn-only.
